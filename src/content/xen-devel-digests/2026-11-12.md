This week, the list discussed getting interrupts to virtual machines faster and adding support for new x86 instruction sets. Baptiste Le Duc suggested splitting NUMA-aware memory claim sets into smaller chunks to ease review, while Oleksii Kurochko refined the virtual interrupt controller support for RISC-V. Jan Beulich posted a series to let guests use APX and re-posted updates for the xstate area and AVX10 support. Denis Mukhin’s series introducing an NS16550-compatible UART emulator also drew feedback regarding build errors and code clarity.

643 messages in 124 threads went through the list from 6 to 12 November 2026. Each item below links to its full thread on lore.kernel.org.

## Back from the archive

### xen/mm: Introduce NUMA-aware memory claim sets

_v7, 3 patches · 2 messages from 1 person · first posted 181 days earlier ·_ [_read the thread_](https://lore.kernel.org/xen-devel/cover.1778272036.git.bernhard.kaindl@citrix.com/T/#u)

Baptiste Le Duc suggests splitting the NUMA-aware memory claim sets patch (the part that manages memory shared between virtual machines) into smaller chunks of under 200 lines each to make review easier. He also notes that quoting a mail in the commit message is unusual and recommends using a Suggested-by trailer instead. He reviewed the per-node free page counter patch and sent his Reviewed-by tag.

## Most discussed

### x86: introduce NS16550-compatible UART emulator

_v8, 26 patches · 32 messages from 3 people ·_ [_read the thread_](https://lore.kernel.org/xen-devel/20261111194800.1070016-1-dmukhin@ford.com/T/#u)

Denis Mukhin’s series adds an NS16550-compatible virtual UART emulator (the part that lets guests talk to a serial port) to the x86 port of Xen. Oleksii Kurochko reports that patches 18/26, 19/26, and 20/26 don’t build because they use a variable declared in a later patch, and patch 13/26 fails with -Werror because it dereferences an uninitialized pointer. Jan Beulich asks why the definitions in patch 2/26 restrict certain bits to MSR and suggests dropping the separate masks for reserved bits to avoid confusion.

### x86: permit guests to use APX

_30 patches · 31 messages from 1 person ·_ [_read the thread_](https://lore.kernel.org/xen-devel/17d56a5d-41f2-4691-aea7-d6dfdde5ad32@suse.com/T/#u)

Jan Beulich posted a 30-patch series to let guests use APX (Advanced Performance Extensions), a new x86 instruction set that adds extra general-purpose registers and faster atomic operations. He notes the work depends on other stalled patches for AVX10 support and VMX instruction handling. No other messages appeared in the thread this week.

### x86 xstate area / AMX+XFD / ACE

_v4, 28 patches · 29 messages from 1 person ·_ [_read the thread_](https://lore.kernel.org/xen-devel/0407294d-d605-41f3-a16b-1505d897ef3f@suse.com/T/#u)

Jan Beulich re-posts a large series that updates the xstate area (the part of the CPU that saves and restores complex processor states) to support new tile-based instructions. He notes that the work sits on top of the APX series and that ACEv2 support is missing for now.

### x86: support AVX10

_v5, 19 patches · 20 messages from 1 person ·_ [_read the thread_](https://lore.kernel.org/xen-devel/1be43887-4494-4ff5-a801-0c6bab90c80d@suse.com/T/#u)

The AVX10 support series (a set of patches to handle the latest Intel vector instruction set) is in revision 5, with Jan Beulich noting that AVX10.1 is mostly a rebranding of existing AVX512 features while AVX10.2 adds new instructions. Jan Beulich mentions the series depends on previous CPUID and emulator patches.

### RISC-V: virtual interrupt controller (vAPLIC/vIMSIC) support

_v3, 39 patches · 19 messages from 3 people · first posted 36 days earlier ·_ [_read the thread_](https://lore.kernel.org/xen-devel/cover.1790779209.git.oleksii.kurochko@gmail.com/T/#u)

Oleksii Kurochko is refining the commit message for patch 32/39 to clarify how the IMSIC virtual interrupt controller (the part that manages per-vCPU interrupt state) handles migration, while also noting he is unsure whether to explicitly mention software interrupt files that aren't yet implemented. Baptiste Le Duc agrees to keep the wording implicit in that patch and suggests introducing real functions before their callers in patch 31/39 to better reflect how the hardware actually works. Jan Beulich questions the logic behind saving certain control registers in patch 11/39, asking whether their values can be reconstructed from other state, and provides an Acked-by tag for patches 14/39 and 16/39 after noting a minor wording nit.

### x86: initial SVM AVIC support

_28 patches · 17 messages from 6 people ·_ [_read the thread_](https://lore.kernel.org/xen-devel/20261105013347.719392-1-dmukhin@ford.com/T/#u)

Andrew Cooper’s patch series (the code that manages AMD’s Advanced Virtual Interrupt Controller) reliably hangs OVMF, as Ross Lagerwall reported after applying the changes. Jason Andryuk asks why the code doesn’t eventually use the VMCB.avic_backing_page directly, while Teddy Astie suggests marking the domain state as \__ro_after_init and warns about potential guest access issues. Jan Beulich asks for documentation updates as suboptions are added and suggests introducing a stub in the patch where it’s needed. Andrew Cooper flags bugs in the vlapic TPR emulation code and argues for using CONFIG_PERF_COUNTERS instead of an ad-hoc mechanism.

### unmap_page_range optimisation

_v5, 6 patches · 16 messages from 3 people ·_ [_read the thread_](https://lore.kernel.org/xen-devel/20261112100005.324440-1-kevin.lampis@citrix.com/T/#u)

Kevin Lampis’s patch series (v5) tweaks the mmu_update hypercall to let Linux fetch and clear page table entries in one go, which speeds up memory unmapping during VM migration. Andrew Cooper reviewed the first patch and shared code size stats for the second patch, noting the changes look right. Jan Beulich asked why the second patch doesn’t pass the old entry into UPDATE_ENTRY to cut down on redundancy, and he flagged missing blank lines in the fourth patch. Andrew Cooper said he can’t find a clean way to return the old value because the current code structure makes it tricky to handle types safely.

### Implement CPU hotplug on Arm

_v11, 6 patches · 10 messages from 3 people ·_ [_read the thread_](https://lore.kernel.org/xen-devel/cover.1794222015.git.mykyta_poturai@epam.com/T/#u)

Mykyta Poturai’s series adds CPU hotplug support for Arm, letting you add or remove processors while the system runs. Jan Beulich acks the sysctl implementation patch (4/6) that exposes the new control interface. Volodymyr Babchuk reviews both that sysctl patch and the documentation patch (6/6).

### tools/libs/guest: re-read dominfo after changing a PV guest's width on restore

_v2, 2 patches · 10 messages from 3 people ·_ [_read the thread_](https://lore.kernel.org/xen-devel/20261111171441.23101-1-gwd@xenproject.org/T/#u)

George Dunlap’s patch to re-read domain info after changing a PV guest’s width on restore (the part that handles migrating 32-bit virtual machines) fixes a bug where the restore process fails or corrupts data if the shared memory page moves. George reports that applying the second patch in the series before the first usually causes the restore to fail cleanly, but applying it after can lead to silent data corruption. Jan asks if the second patch must be applied in order or if it can go in first without making things worse. Andrew says he’s going to write a proper migration test to catch these simple errors.

### Add initial Xen Suspend-to-RAM support on ARM64

_v13, 14 patches · 9 messages from 3 people · first posted 9 days earlier ·_ [_read the thread_](https://lore.kernel.org/xen-devel/cover.1793129971.git.mykola_kvach@epam.com/T/#u)

Mykola Kvach plans to rename a configuration option to suspend_possible and update the commit message to explain why the code skips suspend support for Cortex-R processors. Jan Beulich points out a potential leak where a CPU that fails to come up during resume might not get freed, and suggests setting the frozen_cpus bit to ensure the notification is sent. Bertrand Marquis provides Reviewed-by tags for most of the patches but asks whether the SMMUv3 event queue tasklet should always run on resume to catch events that arrived before the interrupt was enabled.
