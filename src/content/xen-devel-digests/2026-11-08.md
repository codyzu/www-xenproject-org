This week, the list discussed speeding up interrupt delivery and improving address space isolation. Denis Mukhin posted a series adding support for AMD’s AVIC to bypass software emulation, and another series introducing an interrupt latency test to the Xen Test Framework. Jan Beulich reviewed patches for Address space isolation, which received a new command line option, and provided feedback on RISC-V virtual interrupt controller support.

664 messages in 98 threads went through the list from 2 to 8 November 2026. Each item below links to its full thread on lore.kernel.org.

## Back from the archive

*7 patches · 2 messages from 2 people · first posted 96 days earlier · [read the thread](https://lore.kernel.org/xen-devel/38850629-8bfa-4737-99ff-0fd3f489e56e@suse.com/T/#u)*

## Most discussed

### x86: initial SVM AVIC support

*28 patches · 56 messages from 6 people · [read the thread](https://lore.kernel.org/xen-devel/20261105013347.719392-1-dmukhin@ford.com/T/#u)*

Denis Mukhin’s series adds support for AMD’s AVIC (Advanced Virtual Interrupt Controller) to speed up interrupt delivery by bypassing software emulation. Jan Beulich asks for documentation updates to be moved to the patch introducing the option and suggests using dashes instead of underscores. Ross Lagerwall questions whether a check for nested guests actually works since the code runs before the guest is active. Andrew Cooper points out that several patches rely on existing bugs in the CR8 handling logic.

### ASI: HVM through X4

*v6, 44 patches · 46 messages from 2 people · [read the thread](https://lore.kernel.org/xen-devel/20261103-asi-hvm-v6-0-59dbc5ce9615@xenproject.org/T/#u)*

Address space isolation (a security feature that keeps virtual machines from seeing each other's memory) gets a new command line option in patch 06/44. Jan Beulich reviews patch 01/44 and adds a Reviewed-by tag.

### RISC-V: virtual interrupt controller (vAPLIC/vIMSIC) support

*v3, 39 patches · 41 messages from 3 people · first posted 32 days earlier · [read the thread](https://lore.kernel.org/xen-devel/cover.1790779209.git.oleksii.kurochko@gmail.com/T/#u)*

Baptiste Le Duc asks for a clearer explanation of why the vCPU wake-up logic in patch 35/39 is sufficient to prevent missed interrupts, while Oleksii Kurochko agrees to adjust the wording in patch 17/39 to better reflect where MMIO emulation hooks in. Jan Beulich points out that volatile doesn't express the memory clobber needed in patch 21/39, and Baptiste Le Duc suggests splitting a dense comment in patch 37/39 and moving a later patch earlier to fix a reserved encoding issue. Oleksii Kurochko and Jan Beulich also debate whether to strictly follow MISRA rules for integer types in patch 23/39, with Jan arguing that unsigned int is sufficient where it fits.

### Add SMMUv3 Stage 1 Support for Xen guests

*v5, 22 patches · 25 messages from 3 people · [read the thread](https://lore.kernel.org/xen-devel/cover.1793726692.git.milan_djokic@epam.com/T/#u)*

Milan Djokic’s series adds emulated SMMUv3 support (the hardware that manages memory access for devices) to let guests handle Stage-1 translation. Robin Murphy notes that some newer MMU-700 chips don’t need the workaround in patch 07/22 and suggests disabling nested translation is too drastic. Jan Beulich says the new domctl command in patch 21/22 needs to be marked as Arm-only since it isn’t arch-independent.

### x86: add interrupt latency test

Denis Mukhin posted a 15-patch series to add an interrupt latency test to XTF, the Xen Test Framework (the hypervisor’s test suite).

### x86: PVH Dom0 loading rework

*v2, 14 patches · 15 messages from 1 person · [read the thread](https://lore.kernel.org/xen-devel/a1f88104-14ae-400c-b950-163d5a7e552b@suse.com/T/#u)*

Jan Beulich posted the second revision of a series to let PVH Dom0 (the privileged virtual machine) load bigger initrd files without shrinking its memory. He asks for review on patch 10/14, which tries to map the initrd directly into Dom0.

### xen/arm: scmi: introduce SCI SCMI SMC multi-agent support

*v15, 6 patches · 14 messages from 2 people · [read the thread](https://lore.kernel.org/xen-devel/cover.1793717221.git.oleksii_moisieiev@epam.com/T/#u)*

Oleksii Moisieiev posted a patch series that adds support for multiple SCMI agents (the part of the system that lets virtual machines talk to hardware management firmware) on ARM systems. Volodymyr Babchuk reviewed the driver code and approved it, then turned his attention to the documentation patch and flagged several wording and formatting issues. Oleksii Moisieiev responded by agreeing to fix the text and considering a stricter requirement for device permissions. Volodymyr Babchuk noted that the proposed device tree syntax needs adjustment because node names aren't the same as labels.

### CI: updates for XTF jobs

*13 patches · 14 messages from 1 person · [read the thread](https://lore.kernel.org/xen-devel/20261105013701.719658-1-dmukhin@ford.com/T/#u)*

Denis Mukhin posted a series of thirteen patches to overhaul the XTF test suite tooling (the framework that runs Xen tests) so it can orchestrate jobs on both QEMU and real hardware.

### xen/gnttab: XSA-519/520 followup

*6 patches · 13 messages from 3 people · [read the thread](https://lore.kernel.org/xen-devel/20261103152928.2142176-1-andrew.cooper3@citrix.com/T/#u)*

Andrew Cooper sends a six-part series to tighten up the grant table code (the part that manages memory shared between virtual machines) and clean up cache flushing functions. Jan Beulich asks why the grant table code shouldn't use the same RCU locking logic as Arm’s platform operations and questions why that locking is kept at all, while he also notes that the new lock nesting in patch 5/6 is consistent but might be better avoided later. Michal Orzel reviews patch 6/6, and Andrew Cooper points out that speculatively mapping an unconfirmed memory frame is unsafe.

### xen: address MISRA C Rule 11.8 violations

*4 patches · 10 messages from 3 people · [read the thread](https://lore.kernel.org/xen-devel/cover.1793699713.git.dmytro_prokopchuk1@epam.com/T/#u)*

Dmytro Prokopchuk posted a series to fix MISRA C Rule 11.8 violations, which stop casts from removing const or volatile qualifications from pointer types. Andrew Cooper objects to patch 4/4, arguing that freeing read-only memory is absurd and the real bug is livepatch storing heap allocations in const pointers. Jan Beulich notes that patches 2/4 and 3/4 are alternatives to earlier proposals and prefers his own variant for the latter. He also suggests the project needs a unified stance on whether freeing functions should take pointer-to-const before deviating any of them.

## Bugs and security

### BUG: Xen BUG at mce_amd.c:100 (mc_ec2type) on Zen 3; host left wedged, no reboot

*2 messages from 1 person · [read the thread](https://lore.kernel.org/xen-devel/b9a98b3b-d11e-4463-ac80-4145ca991925@cortex-media.de/T/#u)*

Jan Beulich points out that a pointer value in the machine check code (the part that handles hardware errors) is being rotated by 16 bits, which explains why the values look like garbage. He asks if the reporter is using the XEN_MC_msrinject hypercall (a way for virtual machines to inject hardware errors) to rule out external interference. He then suggests removing an `intpose_lookup` call from the `mca_rdmsr` function to simplify how the system reads model-specific registers. Finally, he sends a patch that folds two separate reads into one to help debug the underlying issue further.
